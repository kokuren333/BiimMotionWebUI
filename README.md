# BiimMakerWebUI

企画・資料・演出方針を、Opus 5.5などのファイル・コマンド実行ができるエージェントへ渡す**動画制作ジョブ生成WebUI**です。React / TypeScript / Viteで動く静的アプリで、ブラウザ内で制作に必要なソースコードと設定をZIPにまとめます。

```text
WebUIで企画・素材・設定を入力
  → Motion Job ZIPを生成・展開
  → エージェントが調査・台本・Remotionシーン・音声・音響を制作
  → previewで確認 → build → final.mp4
```

## ローカル起動

このリポジトリの開発環境にはNode.js 22.12以上とnpmが必要です。初回は依存パッケージをインストールします。

```sh
npm ci
npm run dev -- --port 5173
```

[http://127.0.0.1:5173](http://127.0.0.1:5173)を開きます。インストール済みなら、次回からは`npm run dev -- --port 5173`で起動できます。

```sh
npm run build                                     # 配信用のdist/を生成
npm run build -- --base=/BiimMotionWebUI/           # GitHub Pages用
npm run preview                                   # ビルドしたWebUIを確認
```

WebUIにはバックエンド、アカウント、APIキーは不要です。Aivisへの接続や動画レンダリングは、生成ジョブを実行するPCで行います。

## WebUIで設定できること

- **企画・資料**: 動画タイトル、説明目的、対象視聴者、希望尺、参考URL、参考ファイル、動画全体への指示。
- **演出**: デザイン方向性、全画面モード、テンポ、派手さ、モーショングラフィックス量、Biim使用率、数式・図解・チャート方針。
- **キャラクター**: 1人解説 / 2人の掛け合い、名前・読み仮名、性格、口調、役割、表情・動きへの指示、左右の基本配置、各人のGLB、字幕色。
- **音声・音響**: Aivis Engine URL、話者ごとのStyle ID・話速・読み方への指示、添付BGM、簡単なBGM・SEの制作方針。音声合成なしも選択できます。
- **出力・調査**: 横16:9 / 縦9:16、解像度、fps、3Dキャラ登場頻度、追加Web調査の可否、根拠方針。
- **素材の生成**: Codex CLI + imagegenによる画像素材生成の可否（既定は許可）、動画生成AIの使用許可（既定はオフ）。

動画タイトル・説明目的・対象視聴者は必須です。既定は1人解説、横1920×1080、30fps、希望尺300秒、Biimは場面に応じて使用、キャラは頻繁に登場、Aivis音声合成とBGM・SE制作を有効にしています。希望尺は制作目標であり、完成動画の尺は内容と音声の実測値から調整します。

参考ファイルと素材はブラウザのメモリ内で処理し、外部へアップロードしません。参考URLはHTTP / HTTPSのURLを記録し、WebUIでは取得しません。再読み込みすると入力と添付は消えます。使用する添付ファイルの合計は500MB以内です。3DモデルはGLB、BGMはMP3 / WAV / OGG / M4A / AACに対応します。

デザイン方向性の既定文は次のとおりです。入力欄で変更できます。

> Biim形式を軸に、タイポグラフィと図解の動きで理解を助ける。落ち着いた配色に、要所で大胆なアクセント。
>
> ドパガキ向けに最後まで飽きずに見られるように、凝った演出やわかりやすいアニメーションを挿入するように努める。
>
> Biim枠での説明と、画面全体を使ったアニメーションはバランスよくどちらも取り入れる。各キャラクターの3Dモデルは必要に応じてサイズや位置を変更・移動できるようにする。

## MVモード

「01：動画の企画」の制作モードで「MV — 完成音源から制作」を選ぶと、完成済みの音源を使ったMVジョブを生成します。01で曲の雰囲気・世界観と歌詞を記述し、MP3 / WAV / OGG / M4A / AACの完成音源を添付します。音源の尺をブラウザで確認し、制作時にも実ファイルを測定して、希望尺よりその尺を優先します。

MVの入力は01〜03です。02の参考URL・資料・動画全体への指示、03のデザイン方向性を引き続き使用できます。歌詞は01の入力欄へ改行したまま入力でき、画像・資料・データや歌詞ファイルは02へ添付できます。04のキャラクター、05の音声と出力、「演出と調査の詳細」はMVでは非表示です。出力解像度・fpsは現在の設定を引き継ぎます。

既定の指示とデザインは、曲の雰囲気に合うモーショングラフィックスをビート・フレーズ・展開へ同期し、楽曲の構造的変化を映像へ翻訳して、歌詞を構図の要素として設計する内容です。Biim枠は使わず、画面全体を構成します。解説動画とMVで編集した指示・デザインは、モードを切り替えてもそれぞれ保持します。

完成音源は通常のBGMとは別に`assets/music.*`へ保存し、最初から最後まで音量1・ループなしで再生します。Aivis音声、追加BGM・SE、解説字幕、キャラの自動配置は使用しません。通常動画用のBGM・GLBはMVのZIPに含めません。追加Web調査は無効にし、完成音源と提供資料・参考URLを基に制作します。

生成ジョブでは`project.mode="mv"`、`audio.music`、`audio.music_duration_sec`、`direction.music_mood`、`direction.music_lyrics`、`direction.differentiation`を参照します。歌詞入力は`plan/lyrics.txt`にも原文を保存します。`plan/music-analysis.md`、`plan/direction.md`（方向性3案とスタイル定義）、ストーリーボードで楽曲の構成と演出を記録し、Remotionで映像を実装して、音源と映像を確認後に最終MP4を出力します。

### MVの制作原則（思想先的設計）

MVジョブのAGENTS.mdには、制作者kokurenのnote記事「『生成』ではなく『設計』する思想先的AIMV制作完全ノウハウ」の考え方を、既定の制作原則・手順として組み込んでいます。いずれも品質を上げるための原則・手順・チェックリストであり、表現手法を禁止したり、固定のDSLやテンプレートへ縛ったりするものではありません。Remotion / React / SVG / CSS / Canvas / Three.jsは従来どおり自由に組み合わせられます。

- **思想先的設計**: 何を表現するかが先、生成手段は後。楽曲のセクション・ビート・盛り上がりといった構造的変化を、映像の構造的変化へ翻訳します。
- **歌詞の視覚化**: 歌詞を構図の要素として設計します。冒頭のフックでは大きく提示し、字幕的な表示と巨大タイポグラフィの緩急をつけ、歌詞・キャラ・背景の居場所（例：キャラ右・歌詞左）を構図段階で決めます。
- **密度と変化率、強調と抑制**: 画面の情報量と変化の速さを分けて設計し、全編をクライマックスにしません。
- **一貫性**: キャラシートとスタイル定義を先に作ってから素材を量産し、凡庸な「AI slop」的な絵作りを避けます。
- **レイヤー思想（任意）**: 生成素材や参照の上にコード描画のレイヤーを重ねる設計も、選択肢の一つとして示します。
- **検証ループ**: previewを音と一緒に通しで視聴し、スクリーンショットで確認して、「時刻・問題・期待する改善」を対応づけて修正を繰り返します。構造検証と作品評価を区別します。
- **失敗パターンのチェックリスト**: 静止画の並べ替え、フェードとズームだけの反復、歌詞と音のズレ、歌詞末尾の飛ばし、読めない・はみ出す文字、不自然な改行、キャラの一貫性の喪失、ちらつき、技術的に完成しているだけで面白くない映像などを点検します。
- **優先順位**: 今回のユーザー指示 ＞ ジョブ仕様（AGENTS.md / project.json / brief.md）＞ 一般原則 ＞ 過去事例。過去事例の演出・色彩・テンポは無条件に模倣しません。

### 似た作品ばかりにしない仕組み

- 制作エージェントは楽曲分析の後、配色 / タイポグラフィ様式 / モーションの言語 / 構図 / 質感 / テンポ感のうち3軸以上で互いに異なる方向性を3案作り、1案を選んで`plan/direction.md`にスタイル定義を記録します。前作・過去事例・motion-kitの既定値の組み合わせはそのまま踏襲しません。`validate --final`はMVでこの記録も確認します。
- 03の「方向性のたたき台」は、6つの軸を毎回組み替えた3案を表示します。各案は全軸で互いに異なり、「別の組み合わせ」で引き直せます。固定の正解ではなく、必要な要素だけをデザイン方向性へ追記するためのヒントです。
- 03の「差別化メモ」に、前作と変えたい点や避けたい表現を書けます。`direction.differentiation`として保存し、方向性の決定で考慮します。

### MVの入力支援

- 01の歌詞欄の下に、行数・ブロック数・`[Verse]`や`【サビ】`などのセクション見出し・最長行の文字数を表示します。20文字を超える行は、表示時に改行位置とサイズを設計する必要があることを示します。
- 右側の書き出しカードに、必須・推奨・任意の入力状況を一覧表示します。「指示をコピー」の下に、previewで確認する失敗パターンのチェックリストを表示します。
- MVでは01の必須項目名が「MVで表現したいこと」になります。

## 解説モード

制作モードの既定は「解説動画」です。資料や説明したい内容から、視聴者に何かを理解させるための動画のジョブを生成します。MVと同じく01〜03で企画・資料・デザインを入力し、04のキャラクター、05の音声と出力、「演出と調査の詳細」も使えます。必須項目はタイトル・説明目的・対象視聴者の3つで、解説向けに増えた入力はすべて任意です。

この節は利用者向けの紹介です。制作の手順・原則・ゲートの正本は生成ジョブの[AGENTS.md](job-template/AGENTS.md)（「解説動画モード」章と「両モード共通」章）と[生成ジョブのREADME](job-template/README.md)（「解説動画の制作」節）で、ここには写していません。食い違う場合は正本が優先します。

生成ジョブでは`project.mode="explanation"`、`direction.style_mode`、`direction.takeaway`、`direction.prior_knowledge`、`direction.outline`、`direction.differentiation`を参照します（`schema_version`は`0.4`）。構成メモを入力した場合は`plan/outline.txt`にも原文を保存します。制作エージェントは理解設計、方向性3案とスタイル定義、台本と根拠台帳、ストーリーボードを記録してから事前ゲートを通し、シーン・音声・BGM・SEを実装して、preview・finalの確認と事後ゲートの合格をもって完成とします。

### 解説の制作原則（理解先的設計）

解説ジョブのAGENTS.mdは、MVの「思想先的設計」と同じ階層に「理解先的設計」の7原則を置いています。原則の本文と判断の例は[AGENTS.md](job-template/AGENTS.md)の「理解先的設計（解説動画の制作原則）」にあり、READMEでは何を扱う原則かだけを示します。

- **理解ゴール**: 視聴後に視聴者が言えること・できることを先に決め、各場面をそれに照らして残すか削るかを判断します。
- **構造の翻訳**: 因果・手順・比較・定義・数式・誤解の訂正などの説明の型を、映像の動きの型に対応させます（対応表はAGENTS.mdの「説明構造の翻訳」）。
- **認知負荷と変化率**: 新しく出す概念の数と画面の変化の速さを別々に設計します。
- **強調と抑制**: 理解の山場を絞り、そこへ向けて情報量を調整します。
- **正確さ**: 数値・数式・図は根拠と照合し、演出より優先します。この原則と下の事前・事後ゲートは、表現の自由度の例外として守る規則です。
- **キャラは演者**: 視線・指差し・リアクションで説明に参加させます（キャラなしの動画も可能です）。
- **実測尺が正本**: 図・字幕・動きの時間は、合成した発話の実測に合わせます。

ほかの原則・手順は、MVと同じく品質を上げるための考え方であり、表現手法を禁止・固定するものではありません。

### 様式モード

解説動画の見た目の様式を、ジョブごとに03の「様式モード」で選びます。**`biim`は既定であって必須ではありません。** Biimの部品を1つも使わない解説動画も作れます。

| style_mode | WebUIの表示 | 内容 |
| --- | --- | --- |
| `biim`（既定） | Biim 形式 | 枠の中の主映像、右上・右下のノート、下の字幕による従来の形式（`biim-standard-v1`） |
| `anime` | アニメ解説 | 枠を使わず画面全体で、キャラクターの演技と掛け合いを中心に説明する |
| `motion` | モーション解説 | 枠を使わず画面全体で、図形・文字・図解の動きを中心に説明する。キャラクターは任意 |
| `mixed` | 混在 | Biimの区間とアニメ解説・モーション解説の区間を1本の中で織り交ぜる。横向きのみ |

- 様式を変えると、未編集のデザイン方向性の既定文だけがその様式の文に替わります。編集した文は保持します。`anime`・`motion`では全画面の設定とBiim使用率の入力が無効になり（値は保持）、brief・「指示をコピー」の文にBiim枠・ノート欄を使う指示を含めません。
- 縦9:16では`mixed`を選べません。縦の`biim`は枠なしの全画面になります。
- `mixed`では場面ごとの様式を`plan/storyboard.md`と`project.json`の`scenes[].style`に書きます。Biimの枠・ノート・字幕の標準と、`validate`・`qc`のBiim固有の検査は、Biim様式の場面にだけ適用します。
- motion-kitには非Biimの場面向けに`FullscreenStage`（全面シーン）、`StandardCaption`（標準字幕）、`DiagramStage`（図解の全面表示）を同梱しています。使うかどうかは任意です。

### 似た作品ばかりにしない仕組み（解説）

- 解説では、MVの6軸をそのまま使わず、導入の型 / 説明の骨格 / 図解の核 / キャラの役回り / 視覚様式 / テンポと緩急の6軸を使います。見た目より説明の運び方が毎回同じになることが同質化の主な原因なので、軸の大半を説明の運び方に割いています。
- 制作エージェントは理解設計の後に方向性を3案作ります。3案は3軸以上で互いに異なり、説明の骨格か図解の核の少なくとも一方が違う必要があります。1案を選び、選んだ理由と`plan/direction.md`のスタイル定義を記録します。キャラ登場なしの場合は役回りの軸を外した5軸で比べます。
- 03の「方向性のたたき台」は、6軸を毎回組み替えた3案を表示します。視覚様式の軸では4つの様式モードを同格に扱い、Biimに偏らないように様式を選んでからその中の見た目の型を選びます。縦向きでは`biim`・`mixed`の案を出しません。案を追記しても様式モードの選択は変わりません。
- 03の解説用「差別化メモ」はMVの差別化メモとは別に保持し、`direction.differentiation`として方向性の決定で考慮します。前作・過去事例・motion-kitやスターターシーンの既定の組み合わせはそのまま踏襲しません。

### 解説の入力支援

- 01に「理解ゴール」「前提知識と想定される誤解」「構成メモ・台本の下書き」の欄があります。構成メモの下に、文字数・推定読み上げ秒数（話速を反映した目安）・見出し数・ブロック数・最長文の文字数・字幕容量を超える文の数・数値や数式を含む行の数を表示します。
- 右側の書き出しカードに、解説版の必須・推奨・任意の入力状況を一覧表示します。根拠方針が「提供資料の範囲」なのに資料もURLも無い場合、構成メモの推定尺が希望尺と3割以上ずれる場合、追記したたたき台と選択中の様式モードが食い違う場合などに注意を出します。注意は助言で、必須項目が揃っていればジョブを書き出せます。
- 「指示をコピー」の下に、previewで確認する解説版の失敗パターン（23項目）を表示します。項目の定義はWebUI・brief.md・AGENTS.mdで共通です。

### 解説のQC（事前・事後ゲート）

生成ジョブには`npm run qc -- --stage=pre`（シーン実装・音声合成の前）と`npm run qc -- --stage=post`（final・納品記録の後）があります。結果は`reports/qc-pre.*`・`reports/qc-post.*`（JSONと人が読むMarkdown）に出力され、不合格なら終了コード1です。解説動画は事後ゲートの合格（`reports/qc-post.json`の`verdict`が`pass`）が完成の条件です。

- **ゲートにするもの**: 客観的に判定でき、外すと視聴者に実害が出るもの（誤情報、読めない字幕、切れる音声、未確認のままの納品、記録の欠落）。記録の構造・根拠台帳・字幕帯域・ストーリーボードの様式・ナレーション同期・ゴースト走査の実施と照合は機械で、台本と根拠の整合・数値の正確さ・通し視聴などは`reports/qc-review.md`のレビュー行で判定します。
- **助言にするもの**: 面白さ・演出の巧拙・テンポ・スロップ感などの主観的な質と、ゴースト走査の検出件数。合否には入りません。
- レビューは台本を書いたのとは別のコンテキストが行い、用意できない場合は`review_mode: self`を記録します。ゲートの免除はオーナーだけが`reports/qc-review.md`の免除節に書けます。
- 字幕帯域の容量（1行の文字数×行数）は字幕レイアウトから1箇所で算出し、WebUIの統計とQCで共用します。係数は暫定値で、実測による確定は[VERIFICATION.md](VERIFICATION.md)に記録します。
- MVジョブで`npm run qc`を実行しても検査は行わず、終了コード0で終わり、合格のJSONも書きません。

ゲートの一覧と合格条件の正本は[AGENTS.md](job-template/AGENTS.md)の「事前・事後 QC（解説動画のゲート）」と「ゲートと助言の線引き」です。

### 解説の記録ファイル

| パス | 内容 |
| --- | --- |
| `plan/explanation-map.md` | 理解設計（理解ゴール・前提・誤解・主張・山場・扱わない範囲） |
| `plan/direction.md` | 方向性3案・採用理由・スタイル定義 |
| `plan/script.md`・`plan/evidence.json`・`plan/sources.md` | 台本と根拠台帳、出典一覧 |
| `plan/storyboard.md` | 場面ごとの説明目的・構造型・画面状態・様式など |
| `reports/qc-pre.*`・`reports/qc-post.*`・`reports/qc-review.md` | QCの判定とレビュー行 |
| `reports/visual-qa.md`・`reports/delivery.md` | 修正とゴースト照合の記録、納品記録 |

`validate -- --final`は解説ジョブで`plan/explanation-map.md`・`plan/direction.md`・`plan/evidence.json`の欠落を拒否します。書き方のひな形は`plan/templates/`にあり、検査対象のパスには置いていないので、写して使います。各ファイルの工程との対応は[生成ジョブのREADME](job-template/README.md)の「記録ファイル」にあります。

## 素材の生成（Codex CLI + imagegen）

03の「素材の生成」で設定します。既定では**画像素材の生成を許可**し、**動画生成AIは使用しません**。両モード共通の設定で、`project.asset_generation`に保存します。

- 背景画像・透過素材・キャラシート・キャラクターのモーション素材・質感素材が必要な場面では、制作エージェントが生成ジョブの`npm run imagegen`で素材を作ります。このコマンドは`codex exec`をサブプロセスとして起動し、Codexのimagegen skillで生成した画像を`assets/generated/<name>.png`に保存して、`assets/generated/manifest.json`に記録します。`plan/style-sheet.md`があればプロンプトに含め、`--ref`でキャラシートなどの参照画像を渡せます。
- Codexが見つからない・失敗した場合でも、ジョブは止まりません。コマンドは素材を作らずに終了コード0で終わり、manifestに理由を記録します。エージェントはコード描画や提供素材で代替し、未生成の素材を納品記録に残します。
- 動画生成AI（Seedance等）は、03でオンにした場合、またはユーザーが明示的に希望した場合だけ使えます。
- Codex CLIとimagegenの利用には、制作PCでのCodexのセットアップと各サービスの利用条件が必要です。生成した素材の利用条件も確認してください。

## 解説動画のキャラクター・字幕・音声

1人モードではキャラ1を使い、2人モードでは別々のGLBと性格・口調・役割を割り当てて掛け合いを作ります。名前は任意で、各人を`character1` / `character2`で識別します。1人へ切り替えても2人目の入力は保持し、ZIPには使用中のキャラだけを含めます。GLB未添付でもジョブを作成できます。

| 既定設定 | キャラ1 | キャラ2（2人モード） |
| --- | --- | --- |
| 基本配置 | 左 | 右 |
| 役割 | 解説役 | 聞き手・質問役 |
| 字幕色 | 青 `#0000ff`＋白ふち | 赤 `#ff0000`＋白ふち |
| Aivis音声 | kokuren_3rd（ノーマル） | natto-z（ノーマル） |
| Style ID | `1069147200` | `1566366592` |
| 話速 | 1.0 | 1.0 |

字幕色は各人のカラーピッカーまたはHEX入力で変更できます。1人モードでも色を選べます。白ふちは共通です。Style IDと話速も話者ごとに変更でき、同じStyle IDを指定すると同じ声になります。

Aivis Engine URLの既定は`http://127.0.0.1:10101`です。制作するPCでAivisSpeechを起動し、使用する音声モデル・Style IDをそのエンジンで利用できるようにしてください。WebUIは設定をZIPへ保存し、生成ジョブの`npm run voice`が音声を合成します。名前が台本に登場したときは読み仮名を音声へ適用し、字幕の表記を維持します。

### 基本配置と自由なキャラ演出

Biimの2人モードは、既定で**左キャラ1・中央字幕枠・右キャラ2**です。左右の入れ替えや同じ側への配置も選べます。字幕の位置・幅と枠SVGは初期配置から生成し、**各レイアウトの字幕位置は固定します。キャラの移動には追従させません。**

**1人・2人とも、普段は基本位置を保ち、必要な場面では各キャラを独立して自由に移動・拡大縮小・回転できます。** キャラ領域は待機位置の目安であり、移動範囲やサイズの上限ではありません。Biim枠や他の領域をまたぐ演出も使えます。演出後は基本位置へ戻すことを基本とし、キャラ側の配置・サイズ・重なり順で字幕の読みやすさを保ちます。

UIで基本配置と演出方針を指定し、実際の動きは生成ジョブのRemotionシーンに実装します。`Character3D`の`translateX / translateY / scale / rotation`をフレームに同期して変更でき、`BiimScene`の`characterStyle / secondCharacterStyle`で各人の配置や重なり順も調整できます。モデルは初期領域を大きく使うようにフィットし、キャンバスの高さは既定で領域の1.2倍です。具体例は[生成ジョブのREADME](job-template/README.md)にあります。

## Biim・全画面・縦動画

「全画面アニメーション・モーショングラフィックス」をオンにすると、全場面でBiim枠と固定ノート欄を外し、画面全体を映像に使います。Biim使用率を「使わない」にした場合も全画面モードになります。

縦9:16では全画面モードを自動で有効にし、Biim枠は使いません。デザイン文にBiimへの言及があっても、このレイアウト指定を優先します。

| 解像度 | 横16:9 | 縦9:16 |
| --- | --- | --- |
| HD | 1280×720 | 720×1280 |
| Full HD | 1920×1080 | 1080×1920 |
| 4K | 3840×2160 | 2160×3840 |

fpsは24 / 25 / 30 / 60から選択できます。設定は`project.video`とRemotionの出力へ反映し、字幕・キャラの基本配置も向きに合わせます。

Biimを使う動画でも、一部の場面だけ全画面にできます。制作時に`scenes[].biim=false`を記録して`BiimScene`へ渡すと、その場面の映像と、音声の`scene_id`に対応する字幕が全画面レイアウトへ切り替わります。字幕は切り替え先のレイアウトでも固定です。

## 生成ジョブと制作手順

```text
my-video/
├─ AGENTS.md         # 制作工程と演出方針
├─ project.json      # 入力条件、キャラ・音声・レイアウト設定、scenes: []
├─ brief.md          # 原文の指示・資料目録・音響方針
├─ package.json      # runtimeをnpm workspaceで解決
├─ sources/          # 参考ファイル
├─ assets/           # GLB・BGM・枠・フォント・制作時に生成する音声
├─ runtime/          # Remotion / React Three Fiber / Aivis / SE合成
├─ motion-kit/       # 15個の小さなヘルパー（歌詞タイポ・非Biimの提示部品を含む・任意使用）
├─ scenes/           # 動作確認用シーンとタイムライン
├─ plan/             # 台本・構成・音声・音響・出典の計画
├─ reports/          # QA・納品記録
└─ output/           # preview / final
```

1. WebUIで入力し、制作ジョブZIPをダウンロードします。
2. ZIPを展開し、エージェントでフォルダを開いて、UIの「指示をコピー」を渡します。
3. エージェントが`AGENTS.md`・`brief.md`・`project.json`・資料を読み、調査、台本、ストーリーボード、シーン、音声、BGM・SEを制作します。
4. 構造検査とプレビューを行い、映像・音声を確認して修正した後、最終MP4を出力します。

生成ジョブはソースコードと固定バージョンの依存指定を含みます。実行にはNode.js 22以上、npm依存パッケージ、Remotionのレンダリング用ブラウザが必要です。初回セットアップにはネットワーク接続を使います。Aivisを使う場合は別途エンジンを起動します。

生成ジョブ内では次のコマンドを使います。**このリポジトリの`npm run build`はWebUI、生成ジョブの`npm run build`は動画をビルドします。**

```sh
# 展開したジョブのルートで実行
npm install
cd runtime
npm run studio                  # Remotion Studio
npm run voice                   # Aivis音声と発話単位の字幕
npm run sound                   # 簡単なBGM・SEのWAV生成
npm run imagegen -- --name bg --prompt "…"  # Codex CLI + imagegenで画像素材を生成
npm run validate                # 設定・素材・音声タイミング・型チェック
npm run preview                 # output/preview.mp4（半分の解像度）
npm run still -- --frame=30      # output/preview.png
npm run build                   # output/final.mp4
npm run validate -- --final      # 最終成果物と制作記録の検査
npm run qc -- --stage=pre        # 解説の事前ゲート（--stage=postで事後ゲート）
npm run ghost-check             # final.mp4のレンダーゴースト（1フレームだけの要素）走査
npm run ghost-check -- --target=preview  # preview.mp4にも同じ走査（結果はreports/ghost-check-preview.*と静止画）
npm run ghost-check -- --double-render  # もう1本レンダーして全フレーム照合
```

解説動画の同梱シーンは6秒の動作確認用で、`project.scenes`は意図的に空です。制作時にエージェントが場面の目録と`scenes/index.tsx`を編集し、内容と音声の実測尺に合わせて構成します。掛け合いは`scenes[].dialogue`または`plan/narration.json`に発話ごとの`speaker_id`を明記し、話者の音声・字幕色を適用します。

BGM・SEは短い手続き生成WAVを作成でき、添付BGMを優先します。実モデルの口パクやモーションのリターゲットは、モデルのリグに合わせて制作時に実装します。新しい設定やヘルパーを既存の制作ジョブへ反映するには、ZIPを再生成するか該当ファイルを更新してください。

詳しい設定・シーン例・音響例は[生成ジョブのREADME](job-template/README.md)、制作工程は[AGENTS.md](job-template/AGENTS.md)を参照してください。

## Biim枠・書体の標準

Biim場面では`note_top`が右上の要点、`note_bottom`が右下の補足、`script`が読み上げ・字幕です。掛け合いでは`dialogue`を使います。主映像は自由なRemotionコンポーネントで実装します。

`biim-standard-v1`の枠SVGとフォントを毎回ZIPに同梱します。以下は横1920×1080基準・1人モード・左配置・キャラ表示ありの場合の`[x, y, width, height]`です。

| 領域 | 基準座標 |
| --- | --- |
| 主映像 | `[16, 16, 1440, 810]` |
| 右上ノート | `[1498, 34, 388, 182]` |
| 右下ノート | `[1498, 274, 388, 532]` |
| キャラの基本位置 | `[0, 740, 330, 332]` |
| 字幕 | `[350, 870, 1528, 178]` |

2人モードや配置変更時のキャラ・字幕座標は`project.layout.regions`を使用します。背景は`#1e1e1e`、枠線は`#cccccc`、本文・ノートはNoto Sans JP、字幕はM PLUS Rounded 1c ExtraBoldです。字幕の白ふちは基準幅で9pxです。

標準フォントは同梱ファイルから読み込み、完了までレンダリングを待ちます。欠損時はエラーにし、ZIP生成時にもフォントのSHA-256を確認します。標準コンポーネントを使うと枠と書体を共通化できます。フォントの権利表示とOFL全文は`assets/fonts/`に含めます。

## 開発・検証

```sh
npm test
npm run build -- --base=/BiimMotionWebUI/
node --experimental-strip-types tools/make-fixture.ts --duo
cd .verification/smoke-video
npm install
cd runtime
npm run validate
npm run preview
```

`tools/make-fixture.ts`は`--duo`、`--fullscreen`、`--portrait`、`--mv`に対応します。`--mv`は6.25秒の確認用音源と歌詞を含むMVジョブを生成します。指定なしでは横・1人・Biimのジョブを生成します。解説のQC用には`--style=biim|anime|motion|mixed`と`--qc=pass|fail-evidence|fail-caption|fail-review`で様式と合否を選べ、`--out=<dir>`で出力先を変えられます（省略時は`.verification/`）。テストはZIP内容、入力条件、独立したモデル・音声・字幕、レイアウト、添付データ、パス、安全な音声タイミング、音響生成、MVの方向性候補・歌詞の集計・制作原則の同梱、Codex imagegenラッパーの成功・版管理・失敗時の続行（偽のCodexで検証）、テキスト・オーバーレイの合成レイヤー分離とレンダーゴースト検出（単フレーム検出・二重レンダー照合）を確認します。解説モードについては、方向性のたたき台と構成メモの統計、解説のbrief・依頼文・様式モード、AGENTS.mdの解説章とひな形、QCの合格・不合格と様式ごとの検査範囲、`validate --final`の解説記録、非Biimの提示部品も確認します。

検証結果は[VERIFICATION.md](VERIFICATION.md)に記録しています。`validate`は構造検査であり、完成映像の目視・音声確認は制作工程で行います。`validate --final`は本番の制作記録と成果物がない動作確認用ジョブを拒否し、final.mp4のレンダーゴースト走査結果を`reports/ghost-check.md`に助言として記録します（合否には影響しません）。
