## 1. 依頼文（趣旨）

1. MV 制作ハーネスを改良したい。対象は (A) PC ローカルのリポジトリ版 BiimMotionWebUI と、(B) Muse スペース版「MV-E2E」アプリの両方。
2. MV 機能はだいぶ詰まっている。一方で解説動画機能がおざなりになっている。MV 制作で得た知見を解説動画側へ反映してほしい。
3. BiimMotionWebUI の現在の UI がダサい。GitHub Pages の UI に、汎用 AI 生成っぽい没個性で安っぽい見た目（スロップくささ）がある。それを解消したい。
4. 基本ワークフローをこの repo の標準として固定したい。
   - Fable 5.2 = PM：要件だけを詰める（実装しない）
   - Opus 5.5 高 = オーケストレーター：要件を受け取り、計画・タスク分割・関門の判定・差し戻しを行う（自分で全部実装しない）
   - Opus 5.5 中／Codex 6.1 sol high = 実働：実装に取り掛かる
   - そのサブエージェント = 下請け：切り出された小タスクを粗く大量に捌く
   - 環境によってはこの分業ができない場合があるので、できない環境向けの縮退運転も設計する。
5. Claude や Codex を繋いだエージェントに repo を渡したら、その哲学・ハーネス・やり方で自動的に動くようにしたい（repo ルートに自走ハーネスを置く）。
6. この改良作業自体も上記の原則で行う。

## 2. 要件定義書の目的（1.1 の要約）

1. 解説動画の制作ハーネスを MV と同じ水準に引き上げる（設計が先、方向性の複数案、スタイル定義が先、演出目的つきストーリーボード、ゲート、失敗チェックリスト、入力支援を、解説の性質に読み替えて入れる）。
2. WebUI の見た目から汎用 AI 生成テンプレート感を除き、この道具固有のデザイン言語に置き換える。機能は一切落とさない。
3. repo を渡されたエージェントが、階層ワークフロー（PM → オーケストレーター → 実働 → 下請け）と制作哲学に自動で従うようにする。分業できない環境での縮退運転も定める。
4. この改良作業そのものを上記ワークフローで行い、初回の実証とする。

## 3. オーナー決定の追記（Amendment 01、2026-11-13 20:11 JST）

正本：`docs/requirements/2026-11-13-amendment-01.md`。要件書と矛盾する場合はこちらが優先する。

- 指示の原文：「目視しなくても公開していいなと、biimを絶対に守る必要はなく、biimと通常のアニメ解説を織り交ぜたり、通常のモーション解説動画にしたりもできる自由度が必要」
- **AM-1 目視ゲートの廃止**：UI 変更を含む成果物は、機械的ゲート（`npm test`、`npm run build -- --base=/BiimMotionWebUI/`、`npm run qc`（新設される場合）、実装者以外のレビュー、スクリーンショットの取得と `VERIFICATION.md` への記録）に合格すれば、オーナーの目視なしで main へマージし Pages へ公開してよい。スクリーンショットは証拠記録であり待ち点ではない。オーナーの目視は公開後の任意フィードバック。
- **AM-2 解説動画の様式自由度**：解説の出力様式は Biim に限らない。様式モード `biim`／`anime`（通常のアニメ解説）／`motion`（通常のモーション解説）／`mixed`（区間ごとに混在）をジョブごとに選べるようにする。Biim 固有の検査は Biim の場面にだけ適用する。MV は対象外。WebUI 自体のデザイン言語（Biim 枠 UI）は別件で、変更しない。
- **AM-3 決着**：オーナー決定（2026-11-13 20:36、Amendment 02）により、表示名（U3）は `BiimMotion` に統一。repo 名・Pages URL・base パス・package 名は変えない。
